### 1.7 手机 dsh 公网中转（`/dsh/`）

服务器只做跳板，**harness 和手机能力都还在手机上**，公网访问走反向隧道：

```
浏览器 → nginx(443, /dsh/) → 127.0.0.1:18090 → SSH 反向隧道 → 手机 127.0.0.1:3099（网关）→ 127.0.0.1:3080（dsh 本体）
```

手机端的两个文件（在 `/data/user/0/com.deepseek.harness/files/ops/`）：

| 文件 | 作用 |
|---|---|
| `relay.mjs` | ssh2 反向隧道：把服务器 `127.0.0.1:18090` 转回手机 `127.0.0.1:3099` |
| `gw.mjs` | 手机侧网关：`/go` → 302 到**当前有效 token** 的 `/dsh/?token=…`；其余原样转发到 3080（顺带改写 Host/Origin） |
| `tunnel-supervisor.sh` | 常驻守护：网关挂了补网关，隧道断了 3 秒重连 |

手动拉起：`nohup sh /data/user/0/com.deepseek.harness/files/ops/tunnel-supervisor.sh > relay.log 2>&1 &`

**为什么 nginx 要改写 Host/Origin**：dsh 的 `/api` 有 browser-trust 栅栏，会校验 `Host`/`Origin` 与 cookie 里的 authority；`/dsh/` 里那两行 `proxy_set_header Host 127.0.0.1:3080` 和 `Origin http://127.0.0.1:3080` **不能删**，删了就是 400/403。

**本机直连**：`http://127.0.0.1:3099/go` 也能用（网关会把 `/dsh` 前缀剥掉），控制面板的「本机 DSH」就是走这条，任何 App 都能连 loopback。

**老浏览器兼容**：ColorOS 自带浏览器 / 旧 WebView 缺 `Promise.withResolvers`、`AbortSignal.any`，会一直卡在「重新连接」。网关 `gw.mjs` 会往 HTML 里注入这两个 polyfill（`injectHtml`），再遇到新 API 缺失就照这个办法补。

**注意**：`/dsh/go` 等同于 token 链接，谁拿到谁能操作这台手机；没做二次验证，别外传。App 的「设置 → 快捷入口」里「手机 DSH · 公网」就是读 `/api/links` 的 `phoneDsh`（实时 token）。

### 1.8 手机侧常驻、设备控制台与远端重启

**两个 Magisk 常驻脚本**（`/data/adb/service.d/`，开机自动跑，root）：

| 脚本 | 作用 |
|---|---|
| `95-dsh-web-keepalive.sh` | 把 dsh / relay / gw 进程挪出 App 的 cgroup（避开 ColorOS 整 UID 冻结）、`oom_score_adj=-900`、常驻 wakelock；每 10 秒探一次 `127.0.0.1:3080`，连续 3 次无响应就 force-stop 再拉起。关 wakelock：`touch /data/local/tmp/dsh-web-nowake` |
| `96-dsh-tunnel.sh` | root 身份跑 `relay.mjs`（服务器 18090 → 手机 3099）+ `gw.mjs`（3099 → 3080），掉线 3 秒重连。**必须 root**：锁屏时系统只掐 App uid 的出网，root 不受影响（实测 App uid 几十秒断一次、root 跨锁屏 0 次断线） |

日志：`/data/local/tmp/dsh-web-keepalive.log`、`/data/user/0/com.deepseek.harness/files/root-tunnel.log`

**网关的管理接口**（只监听 loopback，不对外）：

| 接口 | 作用 |
|---|---|
| `GET /admin/health` | 存活探针 |
| `GET /admin/restart?key=***已打码***` | 重启 dsh（force-stop + start），key 不对返回 403 |
| `GET /admin/device` | 设备实时数据 JSON：cpu / load / cores / mem / disk / battery / temp / charging / uptime / netRx / netTx / dsh |

**设备控制台网页**：`https://dsh.saisqi.xyz/dev-8f3a2c7d1e`（无尾斜杠）

- 页面在 `/www/wwwroot/device/index.html`，单文件（宝塔风格卡片 + 环形 + 折线，2 秒刷新）
- nginx 在 `dsh.conf` 的 443 块里：`location = /dev-8f3a2c7d1e`（alias 到 index.html）+ `location = /dev-8f3a2c7d1e/api`（反代 `127.0.0.1:18090/admin/device`）
- 页面里 fetch 用**绝对路径** `/dev-8f3a2c7d1e/api`；无尾斜杠时相对路径会被解析成 `/api`（踩过）

**远端重启**：面板 App 设置页「重启 DSH（卡死时用）」→ 调 `/admin/restart` → root 网关执行重启，约 10 秒恢复。

**远端启停/重启**（面板 3.9 设置页三个按钮，任何设备可用）：

- 启动：`GET /admin/start`；停止：`GET /admin/stop`；重启：`GET /admin/restart`
- 服务器侧对应 `POST /status/api/phone/{start|stop|restart}`，任何装了面板的设备都能调
- 进度：`GET /admin/restart/status` → `phase`（idle/stopping/starting/running/stopped/failed）、`attempts`、`lastError`

**息屏省电（A 方案）**：

- 保活脚本每 30 秒检查：息屏 且 网关 `idleSec`（最后一次外部访问距今秒数）≥ 阈值 → `am force-stop` 停 dsh
- 阈值文件 `/data/local/tmp/dsh-autostop-minutes`（默认 30 分钟）
- 停止时写 `/data/local/tmp/dsh-stopped`，保活脚本看到这个标志就**不再自动拉起**
- 任何启动动作会先删标志再拉起；隧道和网关始终常驻，所以息屏状态下仍可远程启动
- dsh 停止期间同时暂停 ping 保活，进一步省电

**息屏网络保活**（防止模型请求偶发超时）：脚本启动时 `dumpsys deviceidle disable`；每 20 秒 ping 一次保持 WiFi 链路活跃；每 60 秒检查并关闭 WiFi 省电。

## 4. 代理节点（38.175.214.249）与 Play 商店问题

### 4.1 节点现状

| 项 | 值 |
|---|---|
| SSH | `ssh -p 20448 root@38.175.214.249` |
| 系统 | Debian 12，1 vCPU / 1 GB / 10 GB（注意：**带不动 QQ/dsh**） |
| Xray | `vless 443 tcp + REALITY(xtls-rprx-vision, sni=www.apple.com)`；`vless 80 ws`；`vless 8443 ws+tls` |
| Hysteria2 | UDP `:8443`（sni=`38.175.214.249.sslip.io`，obfs salamander） |
| 其他 | exim4 占用 25、systemd-resolved 占 53 |

### 4.2 Play 商店下载不动的结论（已验证）

| 测试 | 结果 |
|---|---|
| 节点本机 UDP → 8.8.8.8:53 | 通（124 字节） |
| 节点本机 QUIC → 1.1.1.1:443 | 通（31 字节版本协商） |
| 手机经 SOCKS5 UDP 中继 | 通（54 字节） |
| **手机 VPN/TUN 内的普通 UDP** | **全部无回应** |
| Play 日志 | `DownloadServiceException: CANNOT_CONNECT (8)` + `net::ERR_TIMED_OUT ... Retryable=true`（每 12 秒重试） |

**根因**：Play 下载器 Cronet 优先 QUIC(UDP 443)；v2rayNG 的 VPN 层不转发普通 UDP，导致永远重试、永远「等待中」。
**绕法**：v2rayNG → 路由设置 → **打开「阻断udp443」**，让 Cronet 立刻回退 TCP（TCP 走隧道是通的）。
**备用方案**：换 Clash Meta（TUN 会转 UDP），配置已生成在旧手机 `Download/clash-hy2.yaml`。

## 8. 踩坑记录（省得再走一遍）

1. **Gradle/Kotlin/Compose 会把这台 3.6G 的机器打死** —— 所以 App 用 aapt2+javac+d8 直接编。
2. **别反复 kill/重启 QQ 来刷二维码** —— 会把 QQ 干到 `GPU process isn't usable` 起不来，只能重启服务器恢复。
3. **dsh token 变更是正常现象**，不是坏了；用 `dsh-url` 取。
4. **二维码约 2 分钟过期**，且 NapCat 不会无限续；取码要快。
5. **手机截图要 `screencap`**（屏幕息屏时全是黑图，先 `input keyevent 224` 唤醒）。
6. **v2rayNG 的「绕过所选应用」是白名单直连**——勾选的会被绕过，别勾错。
7. **dsh 的 /api 会校验 Host/Origin**：反代到别的域名时要么用 `--trusted-host` 重启，要么在 nginx 里把 Host/Origin 改写成手机自己的 authority（`/dsh/` 就是这么干的），否则 400/403。
8. **手机 dsh 的 token 变了不影响公网链接**：`/dsh/go` 每次都现取最新 token，不要再去日志里翻。
9. **「一直重新连接」先看浏览器版本**：老 Chromium 缺 `Promise.withResolvers`/`AbortSignal.any` 就直接连不上；网关已注入 polyfill，日志里 `[connection] connection lost` 才是网络问题。
10. **锁屏掉线的元凶是 App uid 被掐网**：把隧道/网关跑在 root（uid 0）就稳了，App uid 几十秒断一次。
11. **nginx 同一个 server_name 重复的 443 块**会让后一个整块被忽略，location 加了却不生效——用 `nginx -T` 对照实际生效的配置，别只看文件。
12. **`alias` 指向文件 + location 以 `/` 结尾**会被拼成 `index.htmlindex.html`（500）；改用精确匹配 `location = /path` 直接 alias 到文件。
13. **无尾斜杠页面的相对 fetch** 会解析成根路径（`/api`），页面里必须写绝对路径。
14. **App 读不到 `/proc/stat`、`/proc/loadavg`**（SELinux），CPU/负载要从 root 网关的 `/admin/device` 取。
15. **判断「dsh 是否在线」不能用连接数**：App 自己会连着 3080，永远有连接。改用网关的 `idleSec`（最后一次外部访问距今秒数）。
16. **`pgrep -f` / `pkill -f` 会匹配到自己的命令行**（命令里含目标路径时），导致脚本「自杀」、调用无输出。用 `[x]` 括号技巧或按 pid 处理。
17. **写到 shell 脚本里的 `$$`、`${var}` 在 JS 模板字符串中会被插值**，用普通字符串数组拼接，避免变量被吃掉。
18. **停止 dsh 后保活脚本会立刻拉起**：必须加 `/data/local/tmp/dsh-stopped` 标志，启动时删除它。
